# Codebase Structure

**Analysis Date:** 2026-03-21

## Directory Layout

```
AsyncDownload/
├── CMakeLists.txt              # Top-level build graph and project settings
├── vcpkg.json                  # Manifest dependencies
├── cmake/                      # Shared CMake modules
├── configs/                    # Runtime config templates
├── docs/                       # Project documentation and analysis notes
├── include/                    # Public library headers
├── libs/                       # Vendored third-party dependencies
├── scripts/                    # Build and utility scripts
├── src/                        # First-party implementation
├── tests/                      # GoogleTest and integration tests
├── .planning/                  # Mapper and planning outputs
├── .codex/                     # Local workflow/config resources
├── .agents/                    # Session history archive and related state
└── build/                      # Generated build artifacts
```

## Directory Purposes

**`src/`:**
- Purpose: First-party implementation of the download client and engine
- Contains: `*.cpp` and `*.hpp` files for core, download, metadata, persistence, and storage modules
- Key files: `src/main.cpp`, `src/client.cpp`, `src/download/download_engine.cpp`, `src/persistence/persistence_thread.cpp`, `src/storage/file_writer.cpp`
- Subdirectories: `core/`, `download/`, `metadata/`, `persistence/`, `storage/`

**`include/`:**
- Purpose: Public API surface for consumers of the library
- Contains: Headers under `include/asyncdownload/`
- Key files: `include/asyncdownload/client.hpp`, `include/asyncdownload/types.hpp`, `include/asyncdownload/error.hpp`, `include/asyncdownload/performance_metrics.hpp`
- Subdirectories: `asyncdownload/`

**`tests/`:**
- Purpose: Unit tests and integration tests for the first-party code
- Contains: `*_test.cpp`, `*_integration_test.cpp`, test entry point, and support fixtures
- Key files: `tests/main_test.cpp`, `tests/download/download_resume_integration_test.cpp`, `tests/support/range_server.py`
- Subdirectories: `core/`, `download/`, `persistence/`, `storage/`, `support/`

**`cmake/`:**
- Purpose: Shared CMake logic and dependency wiring
- Contains: CMake modules included from the root build
- Key files: `cmake/CompilerOptions.cmake`, `cmake/VcpkgDeps.cmake`
- Subdirectories: None

**`scripts/`:**
- Purpose: Build helpers and repository utilities
- Contains: Batch scripts plus performance tooling
- Key files: `scripts/build.bat`, `scripts/build.sh`, `scripts/config.bat`, `scripts/detect_libs.bat`, `scripts/performance/benchmark.py`, `scripts/performance/profiler.py`
- Subdirectories: `performance/`

**`configs/`:**
- Purpose: Sample or template runtime configuration
- Contains: JSON templates used by the CLI config loader
- Key files: `configs/download_options.template.json`
- Subdirectories: None

**`docs/`:**
- Purpose: Project documentation, architecture notes, and performance analysis
- Contains: Markdown docs organized by topic
- Key files: `docs/architecture_zh.md`, `docs/project_requirement_document.md`, `docs/performance/performance_playbook_zh.md`
- Subdirectories: `archive/`, `performance/`

**`libs/`:**
- Purpose: Vendored third-party dependencies kept in-tree for the build
- Contains: Header-only or source-bundled dependency trees
- Key files: `libs/thread-pool/include/thread-pool/BS_thread_pool.hpp`, `libs/concurrentqueue/include/concurrentqueue/concurrentqueue.h`, `libs/googletest/`
- Subdirectories: Dependency-specific trees

**`build/`:**
- Purpose: Generated build output
- Contains: CMake build artifacts, binaries, and test executables
- Key files: Generated by the build system
- Subdirectories: Configuration-specific output trees such as `Debug/`

## Key File Locations

**Entry Points:**
- `src/main.cpp`: CLI executable entry point
- `src/client.cpp`: Public library entry point for `asyncdownload::DownloadClient`
- `tests/main_test.cpp`: GoogleTest test runner entry point

**Configuration:**
- `CMakeLists.txt`: Root build configuration and subdirectory wiring
- `src/CMakeLists.txt`: Library and CLI target definitions
- `tests/CMakeLists.txt`: Test target and discovery setup
- `vcpkg.json`: Manifest dependencies
- `configs/download_options.template.json`: Example runtime options file

**Core Logic:**
- `src/download/download_engine.cpp`: End-to-end download orchestration
- `src/download/http_probe.cpp`: Remote size and range capability detection
- `src/download/range_scheduler.cpp`: Range creation and stealing policy
- `src/persistence/persistence_thread.cpp`: Ordered persistence, flush, and metadata snapshots
- `src/storage/file_writer.cpp`: File open/write/flush/finalize implementation
- `src/metadata/metadata_store.cpp`: Metadata serialization and recovery loading
- `src/core/block_bitmap.cpp`: Durable block state tracking
- `src/core/memory_accounting.cpp`: Global backpressure accounting
- `src/core/path_utils.cpp`: Derived `.part` and `.config.json` path helpers

**Testing:**
- `tests/core/block_bitmap_test.cpp`: Bitmap unit coverage
- `tests/core/memory_accounting_test.cpp`: Memory accounting unit coverage
- `tests/download/range_scheduler_test.cpp`: Scheduling behavior coverage
- `tests/download/download_resume_integration_test.cpp`: Resume path integration coverage
- `tests/persistence/persistence_thread_test.cpp`: Persistence pipeline coverage
- `tests/storage/file_writer_test.cpp`: File I/O behavior coverage
- `tests/storage/metadata_store_test.cpp`: Metadata serialization coverage

**Documentation:**
- `README.md`: Repository overview and usage
- `AGENTS.md`: Local workflow and build guidance
- `docs/architecture_zh.md`: Chinese architecture notes
- `docs/performance/`: Performance-focused documentation and history

## Naming Conventions

**Files:**
- `snake_case.cpp` and `snake_case.hpp` for first-party C++ modules
- `*_test.cpp` for unit tests
- `*_integration_test.cpp` for broader integration coverage
- `*.md` for documentation and planning artifacts
- `*.bat` and `*.sh` for scripts

**Directories:**
- `snake_case` for first-party code directories such as `src/download/`
- Plural collection names for broad buckets such as `tests/`, `scripts/`, and `configs/`
- Topic-based documentation directories under `docs/`, such as `docs/performance/`

**Special Patterns:**
- `main.cpp` is reserved for the CLI entry point in `src/`
- `main_test.cpp` is reserved for the GoogleTest executable entry point in `tests/`
- `index.json` and timestamped Markdown files are used for `.agents/history/`
- `*.part` and `*.config.json` are derived runtime artifacts, not source files

## Where to Add New Code

**New Feature:**
- Primary code: `src/<feature>/`
- Tests: `tests/<feature>/`
- Config if needed: `configs/`

**New Component/Module:**
- Implementation: `src/<module>/`
- Types: `include/asyncdownload/` for public types, otherwise the matching `src/<module>/` header
- Tests: `tests/<module>/`

**New Route/Command:**
- Definition: `src/main.cpp` for the current CLI, or a new command module under `src/`
- Handler: `src/client.cpp` or a module under `src/download/`
- Tests: `tests/download/` or the nearest subsystem directory

**Utilities:**
- Shared helpers: `src/core/`
- Type definitions: `src/core/models.hpp` or `include/asyncdownload/types.hpp` depending on visibility

## Special Directories

**`build/`:**
- Purpose: Generated build output
- Source: CMake configure/build steps
- Committed: No

**`libs/googletest/`:**
- Purpose: Vendored testing dependency
- Source: In-tree third-party code used by `tests/`
- Committed: Yes, but treated as dependency surface only

**`.planning/`:**
- Purpose: Mapper, plan, and phase artifacts
- Source: Workflow-generated planning state
- Committed: Yes

**`.agents/history/`:**
- Purpose: Session archive records required by repository instructions
- Source: Agent/session handoff data
- Committed: Yes
